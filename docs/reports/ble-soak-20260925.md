## 1. 机制回归（settle + credit 重同步，前/后对比）

3 个串口会话，每会话：open → ping×3 → info×3 → 3s 扫描窗（消耗事件、留下 credit 余额）→ close。会话间不复位固件，精确复现前轮失步场景（固件 credit 跨串口会话持久，host 每会话假设满窗）。

| 会话 | 首请求首试即过 | 首条 info 的 credits | 固件 dropped Δ（对上一会话） | 3s 窗事件（观测/固件） | wire_gaps |
|---|---|---|---|---|---|
| 1 | ✅（ping 2.8ms） | 511 | —（基线 0） | 106 / 106 | 0 |
| 2 | ✅（ping 2.8ms） | 661 | **0** | 108 / 108 | 0 |
| 3 | ✅（ping 2.8ms） | 809 | **0** | 110 / 110 | 0 |

- **前轮（修复前，matrix 报告异常 1）**：连续 3 短会话后广播接收 81→35→0，固件 `events_dropped` **+215**；需手工 `grant_credits(128)` 才恢复。
- **本轮（d9288b8 后）**：host 在首次 pump 前主动补一次 128 grant（`_credit_resync_pending`），固件余额在剩余量上累加（511→661→809，饱和式盈余），任何会话开头事件突发都不可能把余额打穿到 0。**+215 → 0，修复实效确认**。代价是余额单调盈余（设计内：固件 0xFFFF 饱和，"满窗生效"不变式成立）。
- 开口毛刺（U-1）：settle 0.6s 内建后 3/3 会话首请求首试即过，与 matrix 轮"未复现"观察一致，settle 保留为标准措施。

## 3. EVT 突发压测（20 循环：扫描 2s ↔ connect/disconnect 交替）

目标 BH4768391（public，上轮 38ms 连上、256 MTU）：每循环 scan_start(2s)→scan_stop→connect→等 EVT.DISC（固件 dm-not-found 自动拆链，无需人为 disconnect）。20/20 循环 connect `status=0`（7.9–202.9ms）、20/20 观察到 EVT.DISC。

**1802 个事件零丢失的四重证明**：

| 证明 | 值 |
|---|---|
| host 观测 app_seq 严格 +1 连续（无洞 = 无"驱逐早于消费"） | observed=1802, max_app_seq=1801, contiguous |
| 对账：host 观测数 == 固件 `events_sent` 增量 | 1802 == 1802 |
| 固件事件帧 wire SEQ 环连续 | wire_gaps = 0 |
| 帧 CRC / 固件侧丢弃 | crc_errors=0, resyncs=0, 固件 dropped Δ=0 |

credit 流控实测（每循环 info 采样）：host 余额随事件消耗递减、低于阈值 32 即写 +128 grant，全会话 15 帧 grant，余额维持 34–158；固件余额 992–1116（重同步盈余），**全程远离 0**，补授循环稳定无振荡发散。

**报告口径澄清（重要，避免后人误读）**：`EventRing.dropped`（本轮突发 778、soak 7702）是**容量 1024 保留窗对"已消费最老事件"的驱逐计数**，不是链路丢失——host 按 cursor `drain()` 不删除事件，总量超 1024 后必然开始驱逐；实际丢失以"app_seq 连续 + wire_gaps + 双端计数对账"为准（以上四重证明均零）。上轮报告的"host ring dropped=0"仅因总量未超 1024。建议后续（非本轮范围）在 host 文档/字段名上澄清该语义。

## 异常清单

1. **【口径澄清，非故障】`EventRing.dropped` 语义**：保留窗驱逐计数而非丢失（见第 3 节），soak 中 7702 属预期行为；零丢失由 app_seq 连续性 + 双端对账证明。建议 host 侧后续澄清命名/文档（未在本轮纪律内改动）。
2. **订阅对随机设备不可达（设计使然）**：环境内无 0xFEF5 设备，真实 notify 通路（含 CCCD 写入与 credit 联动下的 GATTX 事件流）未能在真机端到端验证，留待 SUOTA 设备到位后补测。
3. 方法学：v1 突发脚本在两阶段间重置了 drain cursor 导致统计重复计数（非丢失，已由 v2 的 app_seq 连续性校验排除）；grant 帧计数 shim 首版 CMD 偏移写错（帧布局 CMD@offset 3），v2 修正。
4. 本轮未见开口毛刺、未见 EVT.CONN 晚于响应的采样问题（沿用上轮教训：不假设事件与响应的顺序）。
