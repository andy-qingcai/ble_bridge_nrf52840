### 1.3 三类新特性专项（任务书点名）

1. **FR-F handle 寻址**（read/write/subscribe/unsubscribe 的 handle 模式）：CLI 4/4 ✓、daemon 4/4 ✓、**MCP 0/4**。daemon 侧 `_gatt_addr_arg`/`_subscribe_addr_arg` 等编址单源已备好，MCP 补齐只是给 4 个工具加可选参数并改调 bridge 编址参数。
2. **FR-H 外设模式**（adv-start/adv-stop/notify/set-char/gatt-define）：CLI 5/5 ✓、daemon 5/5 ✓、**MCP 0/5**。FR-H4 的按地址 disconnect、EVT.GATTX subtype 0x01（外设角色写事件）在 MCP 侧无对应透出（事件经 events 原样 hex 透传，可观测但不解码；daemon 有 `parse_gattx_payload` 结构化）。
3. **FR-G 诊断/恢复面**：核实结果——恢复操作以 GATT 原语形式提供（详见本仓库 CLI/daemon 命令面，经 suota/GATT 命令族编排）；**MCP 侧无捆绑的诊断/恢复工具**（属应用编排，不经 MCP 固化）。

## 3. 功能冒烟（零硬件，2026-09-26 实测）

### Part A：call_tool 层 sim 后端全链 — **全绿**

21 工具逐一驱动（`STATE` 单连接 + 模块锁模型如实工作）：

- 生命周期：`open(sim)` → … → `close` → 后续调用干净回 `not_open` ✅
- 链路面：ping(pong=True) / info("blebridge-sim") / scan(0.1s 恰见脚本化模拟设备 02:1A:7F:BA:BE:01 @-52dBm) / connect（按地址+按名双路）/ mtu=0 ✅
- GATT 面（sim 罐头应答）：read / write（带响应+无响应）/ subscribe / unsubscribe 全 status=0 ✅
- 运维面：list_ports(4 候选) / log_level / suota_status / reset / raw(0x09) / suota_abort ✅
- SUOTA 全程：合成镜像 6245B → bytes_written=6245、blocks=4、chunks=28；EVT.SUOTA 事件 4×progress+1×done 全部落入事件日志，dropped=0、wire_gaps=0 ✅

### Part B：真实 stdio 会话（注册二进制本体）— **全绿**

`host/.venv/bin/blebridge-mcp` 子进程 + mcp 2.2.0 客户端全握手：

- initialize：server=**blebridge**，protocol 2025-11-25 ✅
- tools/list：**21 工具**，inputSchema 全部合法（properties 与 `TOOLS` 表逐一对应）✅
- 工具调用信封：open/ping/close 的 `{"ok":true,"data":...}` JSON 字符串逐字节符合契约 ✅
- 缺口在线上复现：`rescue` → MCP 层 `is_error=True, "Unknown tool: rescue"`（未注册工具走协议层拒绝而非 JSON 信封——即客户端在 tools/list 里根本看不到缺口工具，AI 无从调用）✅（作为缺口证据）

**可用性结论**：MCP 服务器当前形态**可安全启用**——已注册路径端到端可用、现有 21 工具行为正确、异常边界干净（call_tool 层永不抛 traceback）；sim 后端使其成为 CI-ready 的零硬件自检载体。缺口全部是"少工具"，不是"坏工具"。
